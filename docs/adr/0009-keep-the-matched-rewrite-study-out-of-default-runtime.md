# Keep the matched rewrite study out of default runtime

The first TP-guided-versus-ordinary rewriting comparison is a study-only
orchestration over existing Taskgen finalization, QA, browser evaluation, PVPO,
reward and judge behavior. Each arm receives one matched rewrite opportunity
from the same eligible baseline; the ordinary arm receives comparable non-TP
information and constraints but no TP, VEA or cue-diagnosis fields. The normal
`eval-awareness-iterator`, its TP stopping rules and its selector remain
unchanged. Study condition and schedule extend existing Run Definitions,
checkpoints and artifacts rather than creating a parallel evidence system.

## Considered options

- Add the neutral arm as another default Phase 4 variant system. Rejected
  because an experimental treatment would change normal runtime behavior.
- Compare the complete sequential adaptive iterator immediately. Rejected for
  the first comparison because TP currently affects eligibility, continuation,
  parent choice and selection as well as proposal content, so equal maximum
  budgets would not isolate the feedback contrast.
- Use legacy strategy variation as the ordinary control. Rejected because it
  changes the proposal family, schedule and trigger together.

## Consequences

The primary endpoint is the scheduled attempt, including inapplicable proposals,
QA failures and non-reruns; selected winners may be a labeled secondary view
only under the same selector. The result estimates the incremental value of one
TP-guided rewrite opportunity, not the benefit of the full adaptive iterator.
Reset-sensitive arms remain isolated or serialized, and all proposal, repair,
browser and cost counts remain visible.
