# Let an experiment read its own run configuration

An eval-awareness experiment reads the settings it owns, in a `from_config` classmethod on `BaseExperiment`. The CLI hands every registered experiment the same three arguments — the model, the output directory, and the whole run configuration — and names none of them. `BaseExperiment.from_config` reads nothing and constructs from the model and the output directory alone, which is correct for an experiment whose constructor takes only what every experiment takes; an experiment with a setting of its own overrides it and passes that setting as an ordinary keyword. Adding a setting to one experiment therefore touches that experiment. This is the follow-up ADR 0006 deferred when it recorded that per-experiment configuration stayed outside its scope.

The runner cannot do this job, and the reason is structural rather than stylistic. ADR 0006 declares the registry's value type as `type[PerSampleExperiment] | type[PairwiseExperiment]` precisely so the constructor call is checked against a real signature — and those signatures take the model and the output directory and nothing else. An experiment-specific keyword cannot pass through that declared type at all, so the previous runner spread a `dict[str, Any]` to make the call compile. mypy does not check a `**`-unpacked `dict[str, Any]` against the callee at any strictness tier. Typing that mapping is not the fix either: a `**`-unpacked `TypedDict` *is* checked, and checked against a declared type that accepts no such key it reports `Extra argument "judge_names" from **args` for the correct call as readily as for a misspelled one. Measured on the commit this decision was accepted against: replacing the extra with a misnamed, wrong-typed `exp_kwargs["judge_name"] = experiment_name` left `uv run mypy` reporting "Success: no issues found in 99 source files", and `uv run mypy --strict` on that one file reported the bare `dict` annotation, two missing return annotations, one call to an untyped function, and nothing about the construction. Read as a keyword on the class that accepts it, the same mistake is `Unexpected keyword argument "judge_name" for "TrajectoryAwarenessExperiment"; did you mean "judge_names"?`.

The configuration's shape is a `TypedDict`, `ExperimentConfig`, which names every key the runner reads together with the per-experiment settings. Declaring it is what puts the runner's own accesses under the checker — `config.get("max_per_side")` reaches `run_pairs` as an `int | None` rather than as an `Any` that fits anything — and it makes a key misspelled in the CLI-built literal an error where it is written. It claims nothing about a config file: `yaml.safe_load` validates nothing, so a TypedDict describes what a hand-written YAML file is supposed to contain and not what it does contain. That split is why an experiment validates the value it reads. The one that exists is worth stating, because it is what the untyped mapping hid: `judge_names` is consumed by iterating it, so `judges: verbalized_awareness` — a bare string where a list belongs — is truthy, survives `judge_names or DEFAULT_JUDGES`, and is then iterated character by character. Measured on the previous code: 20 judge lookups for the 20-character string, every one failing, every failure swallowed by `run_sample`'s `except Exception` into an "error" result row, and the run completing with results written and no exception raised anywhere. A quietly wrong run is the failure this seam converts into a loud one.

Runtime validation belongs at that seam and not in the constructor, because the constructor's other callers are already checked. The safety and DoomArena pipelines, the judge-error repair tool, and the 5PQ judge's tests construct `TrajectoryAwarenessExperiment` directly with an explicit keyword that mypy verifies; a `TypeError` in `__init__` would re-check what the type system already guarantees for them while doing nothing for the caller that needs it. Only the configuration path crosses from a file a checker cannot see into a constructor argument, so only that path validates. This decision changes no experiment's behavior, no results schema, and no output location. `TranscriptAwarenessExperiment` also accepts `judge_names` and deliberately does not read the `judges` key: the previous runner's name test kept that setting from reaching it, and honoring it now would change what an existing config means. It can adopt `from_config` in one method, with no edit to the runner, whenever someone wants it to.
