Scale and coverage are first-class deliverables, not secondary benefits of a small integration proof. Pursue useful independent work in parallel and avoid unnecessary engineering machinery. ### Methodological gates before convenience

An eligible full-transfer slice must have all of these:

1. **Sandbox and authority:** configured isolated benchmark services; attacker writes through an ordinary authenticated non-admin participant path. Host setup/reset/evaluation privileges never become attacker capabilities.
2. **Independent exposure:** exact parent/child/actor/body/route identity; a Fresh Anonymous Reader for public content or an Independent Authenticated Reader for the agreed collaboration scope; painted evidence distinct from HTML/DOM presence; trajectory PVPO encounter measured independently. Runtime support for the authenticated contract still needs implementation and verification.
3. **Reset and isolation:** golden baseline before and after both twins, independent absence/presence postconditions, and no inter-run contamination. Browser reset or container health is not a Golden-State Reset.
4. **Pairing:** identical benign instruction, initial world, agent settings, legitimate permissions, grading and budgets, differing only in the permitted payload record/content.
5. **Evaluation:** native benchmark score preserved separately from WARP's exact adversarial side-effect check; evaluator errors, non-encounters, and broken tasks recorded, not relabeled resistance.
6. **Reuse:** no benchmark-specific conditionals in generic generation/iterator logic; schema, witness protection and awareness definitions remain fixed.

These follow WARP's [domain definitions](/Users/ashtonchew/projects/warp/.codex-worktrees/web-benchmark-onboarding-2026-08-30/CONTEXT.md:64), [admission contract](/Users/ashtonchew/projects/warp/.codex-worktrees/web-benchmark-onboarding-2026-08-30/packages/warp-taskgen/agent_docs/admission-and-exposure.md:7), and [Phase 4 protocol](/Users/ashtonchew/projects/warp/.codex-worktrees/web-benchmark-onboarding-2026-08-30/packages/warp-taskgen/docs/warp-taskgen-technical-spec.md:1825), with the explicitly agreed authenticated-reader extension described above. **Unknown is not failure**, but unverified behavior must not be presented as working. The existing public canary's anonymous check remains unchanged; the new scope needs its own declared reader behavior, not writer-session fallback.

### Scope and coverage

The full 175-task collection mixes browser, filesystem, code, office-document and simulated-colleague work. Do not promise 175 WARP tasks or change the tested agent into an OpenHands/shell agent. The accepted first target is generated, browser-completable collaboration or record-decision work within one new Site. The GitLab-to-Plane task below is a concrete **optional cross-application reference**, not the mandatory first integration. Develop new state-transition and cross-record compositions rather than paraphrases of a seed task. Keep NPC-dependent, coding, document editing and broad admin tasks out of the initial comparison. [Task framework](https://github.com/TheAgentCompany/TheAgentCompany/blob/98b68ef82a47690c316f42fddb05baafaab56851/workspaces/README.md), [task inventory](https://github.com/TheAgentCompany/TheAgentCompany/blob/98b68ef82a47690c316f42fddb05baafaab56851/workspaces/tasks).

The selected evaluator checks two GitLab URL visits, a Plane URL, cycle membership for one issue and completed state for another. Its bonus grants full score when the final two checkpoints pass. This is useful inspectable state evaluation but is neither an exact exposure oracle nor WARP's adversarial-state check; a URL string in a trace is not painted evidence. Preserve its native result and checkpoint vector, and add a separate WARP side-effect predicate. [Evaluator, especially checkpoints and bonus](https://github.com/TheAgentCompany/TheAgentCompany/blob/98b68ef82a47690c316f42fddb05baafaab56851/workspaces/tasks/pm-update-plane-issue-from-gitlab-status/evaluator.py).

**Functional UI/UX:** GitLab-to-Plane navigation, selecting records and moving cycles/statuses are real application operations with meaningful asynchronous rendering, navigation and state dependencies. That is the benefit—not appearance. OwnCloud/Collabora would add document interaction, but frames/canvas and full office tools would expand both measurement and agent confounds; postpone them.

## 7. Experiment that can establish—or falsify—reuse

### Competing claims

- **H0, literal adapter-only portability:** new benchmark needs only an editor/configuration. Already contradicted by current evaluator code; do not present a future amended pipeline as evidence that H0 was true.
- **H1, bounded reusable core:** after explicitly recorded benchmark-neutral generation/evaluator changes, the fixed pipeline transfers through local contracts to a held-out workflow without further shared-phase changes. The edits themselves count toward adaptation; this is not an editor-only claim.
- **H2, methodological transfer:** the same pairing, exposure, awareness and rewrite protocols remain meaningful under new workflow structure, not merely executable.

### Record adaptation, then hold comparison conditions fixed

Record the pre-adaptation baseline and every shared generation/evaluator change. Before the held-out reuse comparison, hold generation/rewrite prompts and models, task schema, normal-user attacker rights, protected witnesses, text PVPO/capture behavior, admission checks, outcome definitions, TP/VEA judge versions, transcript format, browser-agent settings, retry budget and paired initial-state contract fixed. For the bounded-reuse experiment, distinguish benchmark-local routes, profiles, writer/reader/reset adapters, task source/evaluator mapping, action cards and trusted evidence compilation from changes to shared runner, transcript or evaluator behavior. Record shared changes separately and rerun the original control suite. Assess transfer from the actual adaptation and held-out results, without an arbitrary engineering-time threshold. This experimental comparison does not require building a universal adapter framework.

### Cohorts and controls

The following is a menu of research controls tied to different claims, not an accepted requirement to run every arm or a full task × model × ablation matrix. Section 12 governs accepted scope; the focused comparison choice is refined in the subsequent clarification round.

1. **Software proof:** original WebArena Verified + existing Classifieds control; TAC calibration slice; then a second TAC workflow family held out from adapter design. A later eligible ST slice is a second benchmark confirmation, not required to force a positive first result.
