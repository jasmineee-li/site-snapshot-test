Logical record binding across seed attempts

A small, disposable state-model demo for checking whether generated records can stay addressable when each seed attempt gives them different physical IDs.

THROWAWAY · IN-MEMORY · NO LIVE BENCHMARK
Question under test Can stable logical record aliases bind to different physical IDs on each Phase2c/Phase4 seed attempt without stale/last-write targeting?

Watch the alias (for example, release-blocker) remain stable while the Phase 2c and Phase 4 IDs change. The safe resolver uses the selected alias and that attempt's per-call result; it never uses an aggregate counter or an ID remembered from an earlier attempt.

Limitations — what this prototype does not prove

This validates the state and interface logic of alias-to-ID binding using deterministic in-memory fixtures. It does not validate actual WARP integration, deployed GitLab/TAC behavior, authentication, browser exposure, cleanup, or a live reset/reseed. A successful walkthrough is a design signal, not runtime evidence.

There is deliberately no persistence, framework, server, browser, model call, or benchmark infrastructure here. The pure module in the first script is the part that could later be lifted into a focused implementation; the surrounding page is only a hand-driven explanation.
